# Claude Code 如何"驾驭"AI：通俗解析

> 本文档解释 Claude Code 如何通过"Harness 工程"（驾驭工程）来安全、高效地控制 AI。

---

## 一、什么是 Harness 工程？

想象 AI 是一匹**烈马**，力量强大但难以控制。**Harness（驾驭）工程**就是给这匹马配上马鞍、缰绳和刹车，让骑手能安全地利用它的力量。

Claude Code 本质上是一个**AI 控制系统**，它解决了三个核心问题：
1. 如何让 AI 理解复杂任务？
2. 如何防止 AI 做危险操作？
3. 如何让 AI 持续稳定工作？

---

## 二、Prompt 工程：如何与 AI"沟通"

Prompt（提示词）就是你给 AI 的指令。Claude Code 的 Prompt 工程非常精密，分为三个层次：

### 第一层：系统提示词（System Prompt）

这是 AI 的"出厂设置"，告诉 AI：
- "你是谁"（Claude Code 的 AI 助手身份）
- "你能做什么"（可以调用哪些工具）
- "你应该怎么做"（行为规范）

**关键设计**：Claude Code 的系统提示词不是固定的，而是**动态生成**的。它会根据当前环境自动调整：
- 如果在 Git 仓库里，自动加入 Git 状态信息
- 如果用户有 CLAUDE.md 文件，自动读取作为上下文
- 如果启用了 MCP 服务器，动态加入可用工具列表

### 第二层：用户上下文（User Context）

这是每次对话时给 AI 的"背景资料"，包括：
- **CLAUDE.md 内容**：项目特定的指令
- **Memory 文件**：跨会话的记忆
- **当前日期**：让 AI 知道时间
- **Git 状态**：分支、修改文件等

**关键设计**：这个上下文是**缓存的**，一次会话内不会重复读取，提升性能。

### 第三层：动态组装（Context Assembly）

当用户发送一条消息时，Claude Code 会把以上所有信息**智能组装**：

```
[系统提示词] + [用户上下文] + [历史对话] + [当前消息]
```

**关键设计**：这里有很多优化策略：
- **Token 预算管理**：如果内容太长，会自动压缩历史对话
- **重要性排序**：最近的消息优先保留，旧的可以摘要
- **工具结果精简**：长工具结果会被截断或摘要

## 三、安全防护：给 AI 装"刹车"和"护栏"

### 1. 权限模式（Permission Modes）

Claude Code 有五种工作模式，就像汽车的五档：

| 模式 | 说明 | 使用场景 |
|------|------|----------|
| **默认模式** | 每次操作都问用户 | 新手用户 |
| **自动模式** | AI 自己判断（有安全分类器） | 日常开发 |
| **计划模式** | 先给计划，用户批准再执行 | 复杂任务 |
| **绕过模式** | 允许所有（危险！）| 特殊场景 |
| **禁用模式** | 拒绝所有工具调用 | 纯聊天 |

### 2. 权限规则引擎

用户可以设置细粒度的规则，比如：
- "允许 `git status` 无需确认"
- "禁止 `rm -rf` 命令"
- "对 `*.md` 文件的编辑需要确认"

**实现方式**：使用模式匹配（类似正则表达式），支持通配符和条件组合。

### 3. 危险操作检测

系统内置了危险模式识别：
- **破坏性命令**：`rm -rf`, `dd`, `format` 等
- **代码执行**：`eval`, `exec`, `python -c` 等
- **网络操作**：`curl | sh` 等管道到 shell
- **权限提升**：`sudo`, `chmod 777` 等

当检测到这些模式时，系统会**强制要求用户确认**，无视权限模式设置。

### 4. 沙箱机制

对于 Agent 子代理（Subagent），Claude Code 支持：
- **工作树隔离**：在临时 Git 工作树中运行，不影响主工作区
- **远程执行**：在远程环境中运行 Agent
- **权限降级**：子代理可以拥有比父代理更严格的权限

## 四、工具调用：AI 的"手和脚"

### 通俗解释

AI 就像一个**只有脑子、没有手脚的人**。它知道要做什么，但无法直接触碰现实世界。工具就是给它的"手脚"：

- **BashTool**（手）：执行命令、运行脚本
- **FileReadTool**（眼睛）：读取文件、查看内容
- **FileEditTool**（手）：编辑文件、修改代码
- **GlobTool**（望远镜）：搜索文件、批量查找
- **GrepTool**（放大镜）：在文件中搜索内容

### 具体例子

#### 例子 1：读取配置文件

**场景**：用户问"我的数据库配置在哪里？"

**AI 的思考过程**：

```
用户想知道数据库配置。

我需要：
1. 先找到配置文件的位置
2. 然后读取配置文件的内容

让我搜索一下常见的配置文件名...
```

**工具调用流程**：

```
【第 1 步：搜索文件】
AI → 系统：使用 GlobTool，搜索 "**/*.config.js" 和 "**/database.yml"

系统 → AI：找到以下文件：
- src/config/database.js
- config/database.yml
```

```
【第 2 步：读取文件】
AI → 系统：使用 FileReadTool，读取 "src/config/database.js"

系统 → AI：文件内容是：
module.exports = {
  host: 'localhost',
  port: 5432,
  database: 'myapp',
  username: 'admin'
};
```

```
【第 3 步：回复用户】
AI → 用户：
找到数据库配置在 src/config/database.js：

- 主机: localhost
- 端口: 5432
- 数据库: myapp
- 用户名: admin
```

**为什么要分多步？**

就像你找东西：
1. 先想可能在哪些位置（GlobTool 搜索）
2. 然后去具体位置查看（FileReadTool 读取）

AI 也是一样的逻辑，一步一步来。

---

#### 例子 2：同时读取多个文件（并发执行）

**场景**：用户问"帮我看看 package.json 和 README.md"

**传统方式（串行）**：

```
第 1 步：读取 package.json （2 秒）
第 2 步：读取 README.md （2 秒）
总时间：4 秒
```

**Claude Code 方式（并发）**：

```
AI 判断：这两个读取操作互不影响，可以同时进行！

同时发起两个 FileReadTool：
- 读取 package.json （2 秒）
- 读取 README.md （2 秒）

总时间：2 秒（快了一倍！）
```

**为什么 AI 知道可以并发？**

每个工具都有一个属性 `isConcurrencySafe`：

- **读取操作**（FileReadTool、GlobTool）：不会改变任何东西 ✅ 可以并发
- **写入操作**（FileEditTool、BashTool 删除文件）：会改变状态 ❌ 必须串行

就像你可以同时看几本书（读），但不能同时写几支笔（写会互相干扰）。

---

#### 例子 3：编辑文件的依赖关系（串行执行）

**场景**：用户说"把项目的 Node.js 版本要求改成 18，然后更新 package.json"

**为什么不能并发？**

```
错误方式（并发）：

同时执行：
1. 修改 .nvmrc 文件为 "18"
2. 修改 package.json 的 engines.node 为 "18"

问题：如果第 1 步失败了（权限不足），
      第 2 步却成功了，导致不一致！
```

**正确方式（串行）**：

```
第 1 步：修改 .nvmrc 文件
         ↓ 成功
第 2 步：修改 package.json
         ↓ 成功
第 3 步：通知用户已完成

如果第 1 步失败：
- 停止执行
- 报告错误
- 不会执行第 2 步（保证一致性）
```

**AI 如何判断？**

每个工具执行后，AI 会分析结果：
- 成功 → 继续下一步
- 失败 → 停止或重试
- 需要确认 → 询问用户

就像你做事一样，做完一件看下一件，不会同时做几件事把自己搞乱。

## 五、Agent 子代理系统：AI 的"分身术"

### 通俗解释

想象你是一位**经理**，手下有很多**员工**。复杂项目你不会一个人做完，而是：
1. 把任务拆分
2. 分配给不同员工
3. 并行执行
4. 汇总结果

**Agent 子代理就是让 AI 也能这样做——创建自己的"分身"去同时处理不同任务。**

### 具体例子

#### 例子 1：重构项目的多代理并行

**场景**：用户说"帮我重构这个项目，把 JavaScript 改成 TypeScript，同时更新文档"

**传统方式（单线程）**：

```
AI: 好的，我开始重构...

第 1 步：修改 src/utils.js (30 分钟)
第 2 步：修改 src/auth.js (30 分钟)
第 3 步：修改 src/api.js (30 分钟)
...
第 20 步：更新 README.md (15 分钟)

总耗时：10 小时
用户等待：10 小时

问题：
- 太慢了！用户等得不耐烦
- 如果中途出错，前面做的都白费
- AI 一次只能专注于一个文件
```

**Agent 子代理方式（并行）**：

```
AI: 这个任务可以拆分，我创建多个子代理并行执行：

┌─────────────────────────────────────────────────────┐
│                   主代理（你）                          │
│  "创建 4 个子代理，分别处理不同模块"                     │
└─────────────────────────────────────────────────────┘
                          │
        ┌─────────────────┼─────────────────┐
        │                 │                 │
        ▼                 ▼                 ▼
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│   子代理 1    │  │   子代理 2    │  │   子代理 3    │
│              │  │              │  │              │
│ "处理 utils" │  │ "处理 auth"  │  │ "处理 api"   │
│              │  │              │  │              │
│ 30 分钟      │  │ 30 分钟      │  │ 30 分钟      │
│ ✅ 完成      │  │ ✅ 完成      │  │ ✅ 完成      │
└──────────────┘  └──────────────┘  └──────────────┘
        │                 │                 │
        └─────────────────┼─────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────┐
│   子代理 4（并行执行，不阻塞其他代理）                   │
│                                                    │
│   "更新文档"                                        │
│   15 分钟                                           │
│   ✅ 完成                                           │
└─────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────┐
│              主代理汇总结果                           │
│                                                    │
│   "所有子代理已完成："                                │
│   - utils: 转换为 TypeScript ✅                      │
│   - auth: 转换为 TypeScript ✅                       │
│   - api: 转换为 TypeScript ✅                        │
│   - 文档: 已更新 ✅                                  │
│                                                    │
│   总耗时：30 分钟（比串行快 20 倍！）                  │
└─────────────────────────────────────────────────────┘

优势：
✅ 快 20 倍！用户不用等
✅ 错误隔离：子代理 1 出错，不影响其他代理
✅ 专注：每个子代理只负责一个模块，更专注
```

#### 例子 2：子代理的"隔离"机制

**场景**：子代理 1 修改文件时出错了

```
┌─────────────────────────────────────────┐
│  子代理 1 的工作目录（隔离）              │
│                                         │
│  修改了 src/utils.ts                    │
│  但引入了语法错误！                      │
│                                         │
│  出错 → 停止工作                         │
│  报告给主代理："我搞砸了，这是错误信息"    │
└─────────────────────────────────────────┘
            │
            ▼
┌─────────────────────────────────────────┐
│  主代理（不受影响）                       │
│                                         │
│  "收到子代理 1 的报告"                    │
│  "看起来 utils 模块有坑，我换个思路"       │
│                                         │
│  其他子代理（2、3、4）继续正常工作 ✅      │
└─────────────────────────────────────────┘

关键：子代理的出错不会影响到其他代理或主代理
就像公司的一个项目组出问题了，不会影响到其他项目组
```

#### 例子 3：子代理的权限继承

**场景**：主代理在"询问模式"下工作，创建了一个子代理

```
用户权限设置：询问模式（每个操作都要问我）
                    │
                    ▼
        ┌───────────────────────┐
        │      主代理            │
        │  "我要创建子代理处理这个任务" │
        │                      │
        │  权限：询问模式         │
        │  （每个操作都要问用户）   │
        └───────────────────────┘
                    │
                    ▼
        ┌───────────────────────┐
        │      子代理            │
        │                      │
        │  权限：继承主代理        │
        │  也是询问模式！         │
        │  （不能比主代理更宽松）    │
        └───────────────────────┘

安全规则：
✅ 子代理可以比主代理更严格（比如主代理自动模式，子代理询问模式）
❌ 子代理不能比主代理更宽松（防止绕过权限）

就像：
- 部门经理要求"所有报销都要我签字"
- 他手下的员工也必须遵循这个规则
- 员工不能说"我经理要签字，但我不用"
```

## 六、总结：Claude Code 的"驾驭"哲学

### 1. Prompt 工程 = 给 AI 完整的"工作手册"

就像你给一位新员工：
- **公司手册**（系统提示词）：公司的价值观、规章制度
- **项目资料**（用户上下文）：当前项目的背景资料
- **今日待办**（当前消息）：今天要具体做什么

**没有这些，AI 就像在黑暗中摸索；有了这些，AI 就像开了灯一样清晰。**

### 2. 安全防护 = 给 AI 装上"刹车"和"护栏"

就像自动驾驶汽车：
- **刹车**：看到红灯/行人自动停下（危险命令阻止）
- **导航员**：复杂路口问司机确认（权限对话框）
- **护栏**：防止开出马路（沙箱隔离）

**没有这些，AI 可能会"撞车"；有了这些，AI 才能安全行驶。**

### 3. 工具调用 = 给 AI 装上"手"和"脚"

AI 只有大脑，没有身体：
- **手**（BashTool）：执行命令、修改文件
- **脚**（FileReadTool）：读取文件、探索代码
- **眼睛**（GlobTool）：搜索文件

**没有这些，AI 只能空谈；有了这些，AI 才能真正动手做事。**

### 4. Agent 子代理 = 让 AI 学会"分工合作"

就像一位经理：
- 不亲自做所有事
- 把任务拆分成小块
- 分配给不同员工
- 并行执行，汇总结果

**没有这些，AI 只能串行处理，效率低下；有了这些，AI 可以并行处理，效率倍增。**

---

## 最后的一句话

> **Claude Code 的价值，不在于 AI 本身有多聪明，而在于它建立了一整套"驾驭"AI的工程体系。就像驯马师的价值不在于马跑得多快，而在于他能让马听话、安全、高效地奔跑。**

这就是 Harness 工程的意义——**让强大的力量，变得可控可用**。
